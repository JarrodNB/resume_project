## Design specificity

Career evidence, gap responses, and user review make this recognizably Careergrind. The presentation relies on generic cards and peer navigation rather than organizing the experience around evidence → comparison → review.

## What works

- Evidence is distinguished from capability judgments, supporting honest claims.
- AI work has running, failed, completed, and retry states.
- Sections can be excluded without losing edits, and preview uses the current draft.

## Priority issues

1. **[P1] Protect editing effort and make saving explicit.** Local drafts in FinalResumeEditor.tsx:34 and SavedResumeEditor.tsx:30 have no navigation guard or recovery storage found in reviewed files. ResumeEditorActions.tsx lacks clear dirty/saved feedback. Add an unsaved indicator, save confirmation, and navigation protection or recoverable drafts. Suggested command: $impeccable harden.
2. **[P1] Make generated content visible for review.** FinalResumeEditor.tsx:54 offers Save resume before initially collapsed sections, all included. Users can save without seeing content. Provide a visible review entry point and readable overview while honoring the existing collapsed-section rule and keeping the section being worked on open. Suggested command: $impeccable shape.
3. **[P1] Expose how users can answer a gap.** RequirementAssessmentItem.tsx:51 hides explanations, evidence, and responses behind a collapsed verdict row. Add a visible Add evidence action and explain that a gap means missing library evidence. Suggested command: $impeccable clarify.
4. **[P2] Connect the first session into a clear journey.** AppLayout.tsx presents five peer destinations; CareerLibraryPage.tsx lacks a next step to add a job, and LibrarySection.tsx hides manual Add inside collapsed cards. Provide import/manual starting choices and a contextual next action. Suggested command: $impeccable onboard.
5. **[P2] Make saved jobs easier to resume.** JobsPage.tsx:59 lists jobs without search, stage filtering, or unfinished comparison/review indicators. Add search and lightweight next-action information as the list grows. Suggested command: $impeccable shape.

## Cognitive load and emotional journey

Progressive disclosure keeps long documents manageable but also hides discovery and review. Five conventional navigation items alone are not a major defect. Gap verdicts may feel like rejection before the response form becomes visible. Generation builds anticipation; collapsed results mute the payoff. Clear review entry and save confirmation would improve the ending.

## Persona red flags

- First-timer Jordan: manual entry, gap responses, and the next step after library setup are hard to discover.
- Accessibility-dependent Sam: comparison progress lacks the status announcement used for tailoring; successful saves need feedback. Source-reviewed, not screen-reader tested.
- Interrupted mobile user Casey: editor state can be lost on reload/navigation; mobile layout and touch targets remain unverified.

## Minor observations

- GapResponseForm.tsx can keep saying Saved on this job while the user edits again.
- SavedResumeEditor.tsx places deletion alongside editing actions.
- Sign-in has no visible password-recovery path.
- Sign-up copy assumes an existing resume despite supporting manual entry.
- Library changes do not visibly mark an existing comparison outdated.

## Questions to consider

- What should users see immediately after generation to judge whether the draft represents them?
- Can a gap communicate evidence to add before it reads as lack of qualification?
- Could each job advertise its next useful action?
