The weak spots are reliability and edge cases that only show up when something goes wrong. Three detailed reviews ran in parallel: Rails API, Python worker, and web, infra and docs. I checked the findings below against the code myself, except where I say otherwise. Nothing was run.

Fix soon (all done)
[done] Temporary failures become permanent. Fixed: worker/retryable_errors.py classifies rate limits, 5xx, timeouts and network errors as temporary; the worker leaves those messages for SQS to redeliver (with a growing delay) and only publishes "failed" on the last attempt.
[done] LLM calls have no timeout. Fixed: parse_resume_text runs the agent under one overall deadline (WorkerSettings.llm_run_timeout_seconds, 240s, below the 300s visibility timeout). A per-request timeout alone wasn't enough because the OpenAI client retries timed-out requests itself. A deadline hit raises TimeoutError, which counts as retryable.
[done] The import crashes on malformed input. Fixed: ResumeImports::ValidateParsedResumeShapeService checks the JSON structure (object, lists of objects, highlights as strings, skill names as strings) before importing and returns error messages instead of a 500.
[done] Deleting a job breaks its tailored resumes. Fixed: Resume only requires a job when a tailored resume is created, so resumes whose job was deleted (job_id nulled, as the foreign key intends) stay editable. If deleting a job should delete its tailored resumes instead, switch Job to dependent: :destroy.
Worth doing before real users
Abuse limits. Sign-in, sign-up and GraphQL are now throttled (Rack::Attack) and AI usage has per-user limits, but there's still no GraphQL complexity limit (only a depth cap).
Too much database access for the AI worker. The read-only ai_reader role is granted SELECT on every table, including users.encrypted_password. It should be limited to the tables the worker actually reads.
Resume contents go to Langfuse. Full resume text and contact details are sent to Langfuse Cloud by default (include_content=True), and invalid messages are logged in full. Decide whether that's acceptable.
Unhelpful error for corrupt files. Corrupt or encrypted PDF and DOCX files show the generic "The AI task failed" instead of the "unreadable file" message.
No limits on file parsing. The worker doesn't cap the extracted text length or the uncompressed size of a DOCX, which is a zip file.
Endless spinners on the import page.
If the WebSocket rejects an expired token, the page shows "Loading…" forever instead of ending the session.
A task that completes with no usable result, or comes back as NEEDS_USER_INPUT, falls through to the "parsing" spinner.
Unwanted navigation after leaving a page. If you leave /import mid-upload, you get dragged back when the upload finishes.
Null values cause 500s. An explicit null for requirements, nice_to_haves or position hits a database constraint and returns a 500 instead of a validation error.
Tasks can get stuck as queued. This happens if publishing fails with an error other than the queue errors the service catches, and nothing sweeps up stale tasks.
LLM engineering (matters for the portfolio)
The faithfulness evals can pass trivially. They use substring matching, so an invented "Java" passes because "JavaScript" is in the resume, and an expected skill "R" matches nearly anything. Empty output scores a perfect 1.0. The check also ignores titles, descriptions, contact details and education.
Faithfulness is only measured, never enforced. It's the top metric, but production passes the LLM output straight through. A cheap runtime check could drop highlights that don't appear in the source text.
The resume text isn't fenced off as data. The prompt doesn't tell the model to ignore instructions inside the resume, and there's no prompt-injection case in the eval dataset.
Smaller items
Missing spec coverage.
Rails is missing ownership specs for updateJob, moveJobToStage, updateExperience, deleteExperience, resume(id) and aiTask(id).
The worker has no tests for the polling loop itself or for PDF extraction.
Header gaps. Many Rails mutation and type files have a Description: but no Index:, and the five empty Python __init__.py files have no header.
Doc drift. The root AGENTS.md and the README.md describe Terraform and Kubernetes folders that don't exist yet. docs/mvp_plan.md marks only step 3 as done. apps/web/README.md is still the Vite template.
Dev ports open to the network. Postgres, S3Mock and ElasticMQ bind to all network interfaces with default passwords. Binding them to 127.0.0.1 would fix that.
The "fix soon" items are done. Next, I'd recommend the "worth doing before real users" list, starting with the ai_reader table grants, the Langfuse content decision, and the import page spinners.
