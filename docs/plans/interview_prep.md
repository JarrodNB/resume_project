# Interview prep — phased implementation plan

Description: Add career-library-based interview practice with user-written answers and optional AI feedback.

Index:
- Summary and defaults
- Phase 1: Persistence and API
- Phase 2: Question generation and replacement
- Phase 3: Answer feedback
- Phase 4: Interview prep interface

Stop after each task. Do not begin the next task until the current task has been reviewed and approved.

## Summary and defaults

Add an **Interview prep** tab for multiple persistent sets of exactly five personalized non-technical interview questions. Users type their own answers. English only; general interview mix; sets labeled by number/date, newest first, with confirmed deletion. No custom names or archived question history. Questions must be distinct within a set; global uniqueness is not required.

New generation uses the current career library; library edits do not change existing questions. Answers stay separate from the library. Feedback contains coaching and a grounded example, with explicit placeholders for missing facts and no score. Feedback never fills or replaces the answer field.

Technical questions and job-specific generation are future work. Keep extension points for category and job context without implementing those capabilities.

## Phase 1 — Persistence and API

### Task 1 — Store sets, questions, and answers

Add user-owned sets and five ordered question slots per completed set. Store question/answer text and revisions, plus latest feedback and reviewed revisions. Persist independently of career-library content. Cascade question deletion through the owning set; preserve AI task usage records by nullifying their subjects. Generation will populate all five slots atomically in Task 4. Allocate per-user set numbers under a user lock in Task 2. Persisted sets may be empty while generation is pending or failed.

### Task 2 — Expose GraphQL operations

Add user-scoped set list/detail queries and mutations for generation, answer saving, single-question regeneration, feedback, and deletion. Use thin resolvers and Rails business services. AI operations return an AiTask and validation errors and reuse usage limits/subscriptions. Explicit saving allows an empty answer; feedback requires a nonblank answer. Centralize the 1,000-character answer cap in Rails, Python, and UI. Add authorization specs, including cross-user IDs. Confirm deletion in the UI.

## Phase 2 — Question generation and replacement

### Task 3 — Generate personalized questions

Add queued task types for generation and regeneration. Extract reusable library reading from the job-dependent reader without changing gap analysis. Use a Pydantic AI agent, structured output, dedicated prompts, Langfuse, contact masking, screening, and usage reporting. Generate five distinct non-technical questions mixing introductions, strengths, development areas, career goals, and behavioral examples as library evidence permits. Reject unsupported assumptions and empty/unusable library context. Apply existing prompt limits and actionable errors.

### Task 4 — Apply results safely

Persist all five questions atomically. Single-question regeneration receives the old question and other four, and produces one distinct replacement. Confirm replacement of an answered question; retain old content until success, then clear only that answer and feedback. Prevent overlapping operations on a question. Use task identity and revisions to reject obsolete results, preserve content on failure, and handle duplicate SQS results without duplicate persistence or usage accounting.

## Phase 3 — Answer feedback

### Task 5 — Generate coaching and an example

Feedback requests save the current typed answer and queue the question/answer revisions. Return strengths, specific improvements, and a grounded example answer with placeholders rather than invented facts. Screen answers before model use; retain the saved answer on screening failure or unavailability. Store feedback against reviewed revisions. Label earlier feedback outdated after edits; delayed results cannot appear current for newer answers. Never modify the answer using generated feedback.

### Task 6 — Add agent evaluations

Add synthetic Pydantic Evals datasets/runners for questions and feedback. Use deterministic structure checks and subjective evaluation of personalization, variety, non-technical scope, unsupported assumptions, coaching usefulness, and example grounding. Report to Langfuse and run after prompt/model/agent changes.

## Phase 4 — Interview prep interface

### Task 7 — Add navigation and set pages

Add `/interview-prep` and `/interview-prep/:id` and the navigation tab. Provide generation, persistent list, confirmed deletion, and five ordered cards. Reuse AI subscriptions for queued/completed/failed and usage-limit states; restore task state on reload.

### Task 8 — Add answer and feedback controls

Each card has a textarea, Save answer, Get feedback, and Regenerate question. Feedback requests also save the typed answer. Show unsaved changes, saving errors, task progress, and outdated feedback. Warn on navigation with unsaved answers. Disable editing and conflicting operations during replacement. Display feedback/examples beside answers with clear placeholders. Check keyboard access, narrow layouts, and themes.

## Phase 5 — Verification and documentation

### Task 9 — Verify the complete workflow

Rails: ownership, validation, five-question atomicity, saving, deletion, duplicate/stale results, concurrency, usage limits. Python: sparse/empty context, screening failures, malformed output, duplicate questions, replacement distinctness, grounding. Web: multiple sets, reloads, saving, feedback saving, confirmation, failure preservation, outdated feedback.

Run applicable Rails specs, pytest, both new eval runners, web tests/typecheck/lint in Docker. Browser-check generation through deletion, reload during tasks, and editing while feedback is pending.

### Task 10 — Update docs

Update applicable AGENTS.md inventories and local instructions for new feature folders. Document task types, persistence, revision handling, and significant decisions in architecture.md. Record verification results here.
